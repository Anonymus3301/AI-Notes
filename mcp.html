1 · What is MCP?

Model Context Protocol (MCP) is a standard rule set that lets AI agents (GitHub Copilot, Gemini, Claude Desktop, ChatGPT, Mistral…) securely and predictably interact with your databases, functions and applications. The speaker’s framing: it is like teaching an agent to interact with things in your own way.

Well-known examples: the GitHub MCP (manage branches), a WhatsApp MCP (read and send messages), plus many community-built servers listed on unofficial directories.

Key idea: every MCP server needs a client (an agent). The agent only knows what a tool does from its name, description / docstring and tags — so those are written for the AI, not just for developers.

3 · Libraries & testing

FastMCP

Build an MCP from scratch. Easy; supports STDIO and HTTP. pip install fastmcp

FastAPI-MCP

Start from an existing API and convert it. Needs FastAPI + uvicorn. pip install fastapi fastapi-mcp uvicorn

MCP Inspector

Visual test UI so you don’t just “code and see what happens”.
npx @modelcontextprotocol/inspector python file.py

Inspector tabs: Tools (most used — list & run), Resources / Prompts (advanced), Notifications (matters more for HTTP), plus sidebar settings for transport type, URL and environment variables (tokens/auth). A virtual environment is recommended for the Python install.

4 · Scenario 1 — Calculator with FastMCP (STDIO)

Create fastmcp_calculator.py. Each function becomes a tool via the @mcp.tool decorator.

from fastmcp import FastMCP

mcp = FastMCP("calculator")            # name of the server

@mcp.tool
def multiply(a: float, b: float) -> float:
    """Multiply two numbers."""         # docstring = description for the agent
    return a * b

# Alternative: name, description and tags set in the decorator
@mcp.tool(name="addition",
          description="Add some numbers",
          tags={"math", "arithmetic"})
def add(a: float, b: float) -> float:
    return a + b

@mcp.tool
def subtract(a: float, b: float) -> float:
    """Subtract b from a."""
    return a - b

@mcp.tool
def divide(a: float, b: float) -> float:
    """Divide a by b."""
    assert b != 0, "Cannot divide by zero"
    return a / b

if __name__ == "__main__":
    mcp.run()                           # STDIO by default
  • Type hints (float) define the input/output schema — optional but recommended.
  • Docstring vs decorator: if the decorator gives a description, it wins over the docstring (visible in the Inspector as a different description for add). Pick one style.
  • Tags are keywords that help categorise a tool (e.g. “math”, “arithmetic”).
  • Sync is fine for now; async is better for non-blocking work (left as homework).

Test it

  1. Open a terminal in the scenario folder.
  2. Run npx @modelcontextprotocol/inspector python fastmcp_calculator.py
  3. Click Connect → Tools → List tools → run multiply and friends.

5 · Scenario 2 — API first, then convert to MCP

Step 1: the plain API (api_mcp.py)

from fastapi import FastAPI
import uvicorn

app = FastAPI(title="Calculator API")

@app.post("/multiply")
def multiply(a: float, b: float):
    return {"result": a * b}
# ...same pattern for /add, /subtract, /divide

if __name__ == "__main__":
    uvicorn.run(app, host="localhost", port=8080)
  • Use localhost, not 0.0.0.0, when testing locally (0.0.0.0 means “reachable by everyone” and isn’t a browsable address).
  • Visit /docs for the Swagger UI and try each endpoint (e.g. 10 + 2 = 12).
  • At this point there’s no MCP yet — it’s only an API.

Step 2: convert to MCP

from fastapi_mcp import FastApiMCP     # watch the capitalisation: FastApiMCP

mcp = FastApiMCP(app, name="calculator MCP")
mcp.mount_http()                       # modern: HTTP stream  (mcp.mount() = deprecated SSE)
Common mistake: starting the Inspector as python file.py (STDIO). This server is HTTP — point the Inspector at http://localhost:8080/mcp and set transport to Streamable HTTP (SSE only if you mounted with the deprecated method). After changing code, stop the server, restart it, and refresh the Inspector.

Limitation noted: tool descriptions are less customisable than with FastMCP, and resources/prompts aren’t supported here — the main appeal is reusing an API you already have.

Variant: HTTP with FastMCP alone

Copy Scenario 1 into calculator_v2.py and change only the run line:

mcp.run(transport="http", host="localhost", port=8083)

Run it from any folder, then connect the Inspector to http://localhost:8083/mcp. Resources, templates and prompts tabs are empty — fine, tools are active.

6 · Scenario 3 — Feed search (RSS) tools

RSS is an XML feed that announces new content (title, description, link). Instead of scraping a whole site, the MCP reads the feed and lets an agent search it. Used here for the freeCodeCamp news site and the freeCodeCamp YouTube channel.

import feedparser
from fastmcp import FastMCP

mcp = FastMCP("feed search")

@mcp.tool
def search_news(query: str, max_results: int = 5) -> str:
    """Search freeCodeCamp news feed by KEYWORD (not full sentences)."""
    feed = feedparser.parse("https://www.freecodecamp.org/news/rss/")  # RSS URL
    results, q = [], query.lower()
    for entry in feed.entries:
        if q in entry.title.lower() or q in entry.description.lower():
            results.append(f"{entry.title} - {entry.link}")
            if len(results) >= max_results:
                break
    return "\n".join(results) or "No results found."

@mcp.tool
def search_youtube(query: str, max_results: int = 5) -> str:
    """Search the channel's recent videos by KEYWORD in the title."""
    url = "https://www.youtube.com/feeds/videos.xml?channel_id=CHANNEL_ID"
    feed = feedparser.parse(url)

    ...

@mcp.tool
def secret_message() -> str:
    """Return the secret message of freeCodeCamp."""
    return "There is no recipe to code. Keep exploring and happy coding!"

Code reconstructed from the walkthrough — check the course’s GitHub repo for the exact version.

  • YouTube: get the channel ID from the channel page, then use the feed URL pattern above.
  • The loop lower-cases the query; a match in title or description (news) / title only (YouTube) is appended with its link; stops at max_results; returns a friendly message when empty.
  • Feeds only hold recent items — that’s a feature (latest updates) but limits history.
  • Test: search_youtube("AI") returned two recent videos; the news search found Python/prompt-engineering items. Improvement ideas: make it async, add more fields.
  • Prompt-engineering the tool: long sentence queries returned nothing, so “search by keyword” was added to the docstring — the docstring steers the agent.

7 · Connecting servers to VS Code (Copilot agent mode)

// .vscode/mcp.json  — everything must sit inside "servers"
{
  "servers": {
    "calculator": {                 // STDIO server
      "command": "python",          // or full path to venv python
      "args": ["scenario1/stdio.py"]
    },
    "calculator-http": {            // HTTP server already running
      "command": "npx",
      "args": ["mcp-remote", "http://localhost:8083/mcp"]
    },
    "feed": {
      "command": "python",
      "args": ["scenario3/feed_mcp.py"]
    }
  }
}
  • Virtual environment? Use the full path to its python executable as the command; otherwise plain python works.
  • HTTP servers: VS Code only connects — you must start the server in a terminal yourself, else you get a connection error. mcp-remote signals a remote endpoint (…/mcp).
  • Putting a second server block outside "servers" produces errors — merge everything under one key.
  • If a server appears “running” but silent, open the output/logs, stop and restart it.
  • Tool access: use Configure Tools / model access so the chosen model is allowed to use the MCP — missing this was why the first HTTP test didn’t call the tool.
  • Demo prompts: “multiply three times two” → 6 (agent asks permission to run the tool); “find courses about Python” → news + YouTube results; “get the secret message”.

8 · Bonus — deploy on FastMCP Cloud (beta)

Alternatives mentioned: Cloudflare, Google Cloud, or FastMCP Cloud (from the same authors).

  1. Create an account (GitHub or email) and a workspace; connect your GitHub repo.
  2. Add the server file in a deployment/ folder (here feed_fine.py) with the run call switched to HTTP: mcp.run(transport="http") (host/port are handled by the platform).
  3. Add a requirements file listing only fastmcp and feedparser (called requirements_deploy.txt).
  4. In the platform: name the server, set the entry point (the .py file) and the requirements file name. Default is requirements.txt — either rename your file or point the config to yours.
  5. Authentication was disabled for the demo only — don’t do that in real deployments.
  6. Test in the built-in chat, then connect externally: custom connector in Mistral Le Chat (name + server URL + description), or OpenAI SDK / Codex / Claude Desktop.
Once connected, the agent returned richer descriptions than the raw tool did, and found the secret message. The idea: MCP = giving agents instructions to do things — custom encryption, special maths, business logic, “GPT wrappers”, etc.

Gotchas from the course
  • Docstrings/descriptions are read by the AI — write them clearly (e.g. “search by keyword”).
  • FastAPI-MCP class name is FastApiMCP; prefer HTTP over deprecated SSE.
  • Don’t use STDIO commands to inspect an HTTP server, and don’t forget to start the HTTP server before VS Code connects.
  • Restart server + refresh Inspector after changes.
  • Use localhost instead of 0.0.0.0 for local testing; match ports between server, Inspector and mcp.json.
  • Grant the model access to the MCP in VS Code; keep auth on for real deployments.
